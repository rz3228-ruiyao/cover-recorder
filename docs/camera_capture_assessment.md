# 摄像头采集可行性评估

2026-09-16。用户要求：电脑／USB 摄像头优先，同时评估 iPhone 接入；手机方案复杂则放弃。本轮只做只读检查和方案评估，没有打开摄像头、采集画面或安装软件。

后续用户确认“模拟手机拍摄”，要求视频同时带现场声音，并授权推进。现已按 FFmpeg + QtWidgets 辅助面板方案实现；当前能力及验证边界见 [摄像头采集说明](camera_capture.md)。下文保留评估阶段记录。

## 本机结果

- Windows 11 专业版，build 26100。
- Windows Camera/Image 设备查询未返回实体摄像头；FFmpeg DirectShow 枚举仅显示 OBS Virtual Camera，以及 Focusrite 音频输入。虚拟设备被枚举不代表已经验证能取到画面。
- 本地 JUCE 8.0.12 有 Windows CameraDevice、预览组件和文件录制接口；当前应用未链接 juce_video，也未启用 JUCE_USE_CAMERA。
- JUCE Windows 摄像头代码使用 DirectShow / WMV3 写出纯视频，内置编码配置约 0.895 Mbps，高质量选项目标 30 fps。第一帧时间包含默认 100 ms 延迟估计，不能当作声卡与摄像头精确同步的依据。
- JUCE 的 startRecordingToFile 返回 void，内部录制初始化可能失败，必须另外检查文件和帧，不能调用后就显示“录制成功”。
- 现有 PySide6 的 QtMultimedia 在当前 Conda 环境中导入时报 DLL 缺失。因此暂不能把 Qt 摄像头组件当成开箱可用的备选；本轮没有为评估修改依赖。

## 电脑／USB 摄像头

可行，属于中等规模扩展。音频继续由 Tracktion/Focusrite 独立录制；视频采集与停止保留／丢弃、工程切换和关闭状态联动，再接现有 MP4 导出。

建议先做单摄像头、720p/30 fps（设备支持时）、预览、随 Record/Stop 控制、保存独立视频、自动关联本次 take，保留手动偏移。采集失败时明确反馈并保留已录音频。暂不做多机位、直播、自动漂移校正或手机端应用。

### 用户补充的录制流程

用户接受点击 Record 到实际演奏之间的准备时间，不要求低启动延迟。期望 Stop 后同时保留独立视频和音频，再自动合成成品。

据此采用：准备摄像头 → 两路就绪后显示正在录制 → Stop 停止两路 → 等待 WAV 和视频各自完成落盘 → 渲染当前混音 → 合成 MP4。最终音轨使用包含伴奏和乐器的混音。原始 WAV、视频和混音保留；合成失败允许重试，不要求重新演奏。停止后的视频编码收尾未完成时不能立即开始合成。

准备时间不作为首要优化目标，但演奏前等待不会自动消除两路文件起点差；仍需记录起点关系并在合成时补偿，保留手动修正。摄像头采集不能因画面准备尚未完成而提前播放伴奏。录音过程中关闭窗口、切换工程或再次录制的行为，应受准备／录制／收尾／合成状态约束。首版只针对一次连续演奏，不把替换重录后的整条混音自动配上旧视频。

实现前应先做独立小验证，比较 JUCE 录制输出质量与 FFmpeg DirectShow 采集。倾向复用 FFmpeg 的编码与错误反馈，但实时预览和文件录制必须共享同一个采集源，避免两个进程分别占用同一摄像头。不要直接采用 JUCE 默认 WMV 参数后就宣称高质量采集完成。

验收重点是新边界：设备打开／占用／断开、有效录像与正常停止、音频启动延迟、视频和声卡时钟的持续偏差。短片能验证启动偏移，代表实际歌曲长度的录制才能评估长期漂移；无需重做旧功能的全部验收。

当前缺少实体摄像头，只能准备代码或用可控虚拟视频源验证；不能宣称真实摄像头已通过。

## iPhone

苹果官方连续互通相机面向 Mac，不能直接套到当前 Windows 工程：[Apple 官方说明](https://support.apple.com/en-is/102546)。Windows 的系统“连接的摄像头”功能要求 Android，不适用本用户的 iPhone：[Microsoft 官方说明](https://support.microsoft.com/en-us/windows/apps/phonelink/use-your-mobile-device-s-camera)。

低成本候选是借助已有桥接软件，让 iPhone 作为 Windows 摄像头来源。Camo 官方说明支持 iPhone 与 Windows，通过 USB 或 Wi-Fi 连接：[开始使用](https://camo.com/support/camo/camo-getting-started)、[FAQ](https://camo.com/support/camo/camo-faq)。它是可行候选，不代表本应用与其驱动已实测兼容，也不保证所有画质选项免费。

决定：优先通用电脑／USB 摄像头入口。iPhone 仅保留“现成软件提供兼容摄像头时复用同一入口”的可能性；不开发 iPhone App、专用无线传输协议或驱动。若桥接安装或兼容性处理超出小验证范围，保留原有手机录像导入流程。
