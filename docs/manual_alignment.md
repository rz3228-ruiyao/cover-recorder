## 使用

在项目根目录运行：

```powershell
conda run --no-capture-output -n cover-syncer python -m cover_syncer
```

1. 选择视频和高质量外部音频，确认导出位置。
2. 不必点击自动分析，直接设置“手动修正值”。未分析时，自动估计按 0 ms 计算。
3. 正值表示让声音更晚出现：例如 +300 ms 在音频前补 300 ms 静音。负值表示让声音更早出现：例如 -300 ms 裁掉音频最前面的 300 ms。0 表示不移动音频起点。
4. 点击导出。已有同名文件时，默认不覆盖；确认后才会在新文件导出成功时替换。
5. 用播放器打开导出文件试听、观看，必要时调整后重新导出。

自动分析仍可使用，最终偏移始终等于“自动估计 + 手动修正”。重新分析会清除旧自动估计，保留当前手动修正；分析失败后自动估计保持为空，仍能手动导出。

“清除自动估计，改为手动”把当前最终偏移转成整数毫秒的手动值。手动输入范围仍为 ±600000 ms。切换视频或音频时，两种偏移都清零，避免混用上一组素材的结果。

输出保留第一条视频流（不重新编码画面），只使用所选外部文件的第一条音轨，编码为 AAC。视频时长决定输出长度；音频不足补静音，超出截断。负偏移裁掉全部音频或正偏移超过视频时长时，输出静音视频。AAC 编码可能产生一个音频帧量级的尾部取整。

## 关键改动及理解

- `src/cover_syncer/app.py`：移除自动结果作为导出前置条件，增加明确的 busy 状态。自动结果只决定偏移数值，任务是否正在运行决定控件能否操作。
- `analysis_worker` / `export_worker` 由窗口持有到线程结束。这样 `start_analysis()` / `start_export()` 返回后，worker 仍有明确的 Python 所有者。结果和清理使用窗口的 Qt Slot；线程结束后释放引用并恢复控件。
- 工作期间禁止修改素材、偏移、重复启动任务及关闭窗口；等待任务结束后可以关闭。此版本没有取消任务按钮。
- `src/cover_syncer/media.py`：检查真实文件、输入输出同路径及硬链接别名、媒体流和视频时长；规范音频时间戳。先导出到目标目录中的临时文件，验证音视频流存在后发布；失败保留原输出。未授权覆盖时，发布操作也拒绝抢先出现的同名文件。
- `workflow.py`：无参考音的提示明确引导手动导出。

验证内容：

- 无自动结果直接导出；无参考音自动分析失败后继续导出。
- 可预期与意外分析异常恢复；清除旧自动结果；自动值叠加手动修正；切换两种输入均重置。
- worker 在函数返回和垃圾回收后仍运行；busy 时禁止重复任务及关闭；任务结束恢复控件并释放引用。
- 导出失败不显示成功；覆盖确认接受/拒绝；输入路径保护。
- 生成 3 秒、25 fps 视频，原音轨为 440 Hz；外部音频长 2 秒，在 0.60–0.78 秒及 1.25–1.43 秒放置 880 Hz 标记。
- 分别对有/无参考音视频验证 -3000、-800、-300、0、+300、+4000 ms，共 12 组；预先设定声音起止检测容差 **25 ms**。通过解码音频检测 RMS 和主频，确认指定音频来源、实际时间位移、补静音及完全移出视频的静音行为。
- 对导出前后每一帧的解码校验值进行比较，确认画面及帧时序一致；5 秒外部音频导入 3 秒视频时，输出按视频长度截断。
- 缺失/损坏素材、错误流类型、非法偏移、无效输出路径、原素材硬链接、编码失败保留旧输出、导出期间出现同名文件均检查。
- 对输入素材导出前后计算 SHA-256，确认内容没有改变。
