## 后续程序化验收

应用与检查程序共用 `Source/SessionOperations.h` 的加载、保存、缺失素材检查和渲染逻辑。`--check-session` 不创建窗口、不初始化音频设备，只写新建的隔离目录；用户工程及其媒体不会被保存覆盖。

`tests/verify_native_session.py` 对合成工程和上面的实录工程分别检查：

1. 加载后片段位置、裁剪偏移、边缘淡化、增益、静音和轨道音量，以及保存的输入绑定保持一致。
2. 保存、销毁 Edit、重新创建并加载，状态一致；合成工程同时检查视频路径和偏移字段。
3. 重开前后分别渲染，解码后的所有音频样本完全一致（最大差值 0）；输出并非静音。
4. 重复导出使用不同文件名，第一次 WAV 的全部字节不变。
5. 错误根节点、空文件和损坏 XML 均拒绝加载，保留当前 Edit，拒绝的文件不变。
6. 缺失源音频时阻止渲染，不创建输出目录，不损坏已有 WAV。
7. 用户工程和所有源 WAV 的 SHA-256 不变。
