# 频谱对齐接入与验证

日期：2026-09-18。用户在离线实验后授权继续推进，将分频带频谱接入自动分析。它扩展了现有 MVP 的对齐能力，未修改录音引擎、采集设备控制和原文件保护策略。

## 现有应用如何使用

`workflow.analyze_media()` 仍提取 48 kHz 音频，经 `estimate_offset_from_files(..., robust=True)` 调用新的 `spectral_sync.estimate_offset_hybrid()`。独立 Python 对轨界面与摄像头 Stop 后的后台分析共用该入口。原生手动视频导出仍使用用户指定偏移。

旧的 `estimate_offset()` 和 `estimate_offset_robust()` 保留原行为，用于实验对照和既有调用；没有把旧基线改成新算法后再比较自己。

当前源码以 editable 模式安装在本机 cover-syncer 环境，新后台进程直接加载新代码。无需重编译 C++ exe；已打开的独立 Python 对轨窗口需重新启动才会加载变更。

## 特征与候选

- 输入按单声道转换并重采样到 16 kHz；默认 100 Hz 特征步长。
- STFT 使用 64 ms Hann 窗 / 10 ms 步长，聚合为 80–6500 Hz 范围内 48 个对数分布的三角频带。
- 对频带功率做对数压缩、逐频带去均值和标准化，设置标准差下限，限制低变化频带放大。
- 分批计算频谱，避免长录音时同时持有完整复数 STFT 矩阵；仍需在内存中保存音频和压缩后的特征。
- 分别对频谱特征及原有 RMS 包络求时间互相关，按实际重叠部分能量归一化，至少要求 5 秒及较短序列 50% 的有效重叠。
- 次峰排除区为主峰 ±100 ms，保留对常见错一拍情况的检查。

候选分数 ≥0.35、峰比 ≥1.25 时视为有一定支持。优先使用有支持的频谱候选，其次是包络候选。证据薄弱时仍可返回候选用于人工检查；没有有效信号时明确报分析错误并保留手动路径。

本轮没有采用多频带起音特征作为生产方案。它在先前实验的生成样例中有效，但两组实录的绝对分数较低。

## 自动导出门槛

实验中的接受门限没有直接变成自动导出条件。`high` 必须同时满足：

1. 最终使用频谱候选，相关分数 ≥0.60、峰比 ≥1.50。
2. 有效重叠能划分为至少 2 个互不重叠的参考片段，每个至少约 3 秒，最多使用 3 个片段。
3. 每个片段独立搜索整条外部音频，不把搜索限制在全局候选附近；全部分段都要有足够的分数与峰比，并与全局候选相差不超过 40 ms。
4. 如果包络和频谱候选都获得支持，两者不得相差超过 40 ms；发生冲突则标为 low。

不同片段出现偏移差异、某个片段匹配不够明确，或者没有足够长度做独立分段复核，都不能直接自动导出。较短音频或频谱不可用时可能仅给出包络候选，其可靠性不提升为 high。

这些门限仍是保守工程规则，不是校准后的正确概率。新的规则会把部分实际正确但证据较弱的输入保留在手动确认流程，这是预期行为。

`SyncResult` 增加候选方法、判断原因及两种方法的偏移。Python 界面将“置信度”改为“相关分数”，并显示需要手动确认的原因。原生导出 JSON 继续兼容原协议，附带方法与可靠性诊断字段；`needs_manual` 仍不代表导出成功。

## 新样例复核

运行 `experiments/evaluate_hybrid.py`，使用未参与先前实验的种子 3000–3019；沿用原生成器的 7 类场景，共 140 组：

| 场景 | 数量 | 偏移误差 ≤40 ms | 判为 high | 错误 high |
| --- | ---: | ---: | ---: | ---: |
| 非规则干净演奏 | 20 | 20 | 20 | 0 |
| 等节奏、等响度、不同音高 | 20 | 20 | 20 | 0 |
| 滤波、回声与噪声 | 20 | 20 | 20 | 0 |
| 两路伴奏比例不同 | 20 | 20 | 20 | 0 |
| 失真及更强噪声 | 20 | 20 | 20 | 0 |
| 同音周期重复 | 20 | 不设唯一真值 | 0 | 0 |
| 节奏相同但旋律不同 | 20 | 无有效对应 | 0 | 0 |

这是针对特定问题的受控生成实验，多个场景共享同一种子的旋律，不代表独立真实录音集或通用准确率。

两组已有实录结果：

| 素材 | 用户先前确认值 | 新候选 | 可靠性与行为 |
| --- | ---: | ---: | --- |
| 手机视频 + 外部 WAV | +3320 ms | +3320 ms | low，保留手动确认 |
| 摄像头视频 + 混音 | +560 ms | +550 ms | low，保留手动确认 |

两组全局候选与此前认可值相近，三个分段的候选位置也接近，但各有一个分段的匹配强度 / 唯一性未达到复核门槛；全局分数约 0.366 / 0.397 也低于 high 的 0.60 要求。因此没有为了让这两组自动通过而降低门限。用户认可值不是采样级实验室真值，差 10 ms 不等于改进或恶化了实际同步质量。

## 自动化验证

完整回归：**88 passed in 32.37s，0 failed、0 skipped**，包含现有录音辅助程序、媒体格式、手动导出、Qt 状态和原生进程集成测试，另含 5 个离线实验检查。

新增生产算法检查覆盖：

- 等能量音符、正负偏移、±非整数特征帧偏移、16 / 22.05 / 48 kHz 输入和立体声增益差异。
- 同音反复、完整旋律乐句重复、不同旋律同节奏不能高可信自动通过。
- 中途剪切造成偏移变化、1% 时间伸缩不能伪装成一个可靠的固定偏移。
- 两种强候选冲突，即使分段位置一致也要求人工确认。
- 重叠不够分段时保留候选但不判 high；空、静音、非有限输入报错。
- 实际 WAV 文件入口使用频谱候选且源文件字节不变；结果可序列化。

现有实际 FFmpeg 生成采集 → 提取原声 → 对齐 → 合成测试继续通过，并验证生成演奏的 300 ms 位移及成品可听标记；没有重复用户演奏。

另将两组真实素材通过已安装原生 exe 的 `--check-video-job` 入口调用，启动环境仅保留 Windows 系统 PATH。两组均正确返回“需要手动确认”，未创建误报成功的成品，也未覆盖原始文件；报告为 `tmp/spectral-alignment/integrated-native/results.json`。这验证原生进程 → Python 新算法 → 手动退路的实际连接，不等同于重新点击窗口或重新演奏。

```powershell
$env:COVER_RECORDER_TEST_EXE = (Resolve-Path 'native/cover_recorder/build/windows-vs2026/CoverRecorderNative_artefacts/Release/Cover Recorder.exe').Path
$env:QT_QPA_PLATFORM = 'offscreen'
conda run --no-capture-output -n cover-syncer python -m pytest tests experiments/test_spectral_alignment.py -q -ra
conda run --no-capture-output -n cover-syncer python experiments/evaluate_hybrid.py --output tmp/spectral-alignment/integrated --seed-start 3000 --seeds 20
```

本机完整测试报告：`tmp/spectral-alignment/integrated-tests.xml`。样例结果：`tmp/spectral-alignment/integrated/hybrid-results.json`。可选 `--real-pairs` 格式沿用离线实验，本机私人清单不纳入源码。

## 保留的边界

未实现时钟漂移校正、DTW、音高移调匹配或分离伴奏。失真严重、频带缺失、音色 / 内容差异大、重复乐句均可能让结果不可靠。窗口长度与门限没有进行大规模真实数据调参；自动导出仍应以低错误接受率为目标，保留手动偏移、分析失败恢复和源文件保护。
